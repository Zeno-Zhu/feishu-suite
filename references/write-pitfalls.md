# 写入飞书文档 · 踩坑清单

写给「往飞书文档里写内容」这件事。工具是 `lark-cli docs +create / +update / +media-*`。

---

## 四条最容易翻车的

### 1. Markdown 表格会被打散成碎片文本

Markdown 的 `| a | b |` 通过 Markdown 导入**不会**变成表格块，
Table block 会被跳过，结果是**一堆散落的文本**。

→ **必须建原生表格块**。用 `lark-cli docs +update` 的块操作，或先建表块再填单元格。
（用 `block-types.md` 里的 `table` / `table_cell` 类型。）

**判据**：写完 Fetch 回来，如果表格内容变成了连续纯文本行，就是这个坑。

### 2. `$` 会被当 LaTeX 公式

飞书把 `$...$` 当行内公式。

- ❌ `$82.78` → 渲染成公式
- ❌ `价格 $99` → 同上
- ✅ `82.78 美元` / `USD 82.78` / `￥99`

**凡是内容里有金额、shell 变量、价格表，先全局替换掉 `$`。**

### 3. 分块追加，且尽量一次性导入

- **单次追加内容过长会 400**。保守按 **≤1500 字** 分块；长报告分 4–5 次。
- 按**章节**自然分块，不要从段落中间断开。
- ⚠️ **反复 `--mode append` 会在代码块内部多插空行**。
  → 只要可能，**把正文一次性 `+create` 导入成文**，不要靠多次追加拼。
  → 代码块内容必须**逐字一致**，"多了空行"是 bug，不是可接受的归一化差异。

### 4. 路径只认相对路径

`--file` / `--output` / `--output-dir` / `@file` **只接受 cwd 下的相对路径**，
传绝对路径直接报 `unsafe file path`。

→ 大数据/长 JSON 走 **stdin**，绕开路径与转义：

```bash
cat payload.json | lark-cli docs +update --as user --doc <id> --mode append
```

## 格式：什么渲染得好，什么会坏

### 好用

| 写法 | 效果 |
|---|---|
| `# ## ###` | 标题层级 |
| `- ` + 2 空格缩进 | 无序列表嵌套 |
| `1. 2. 3.` | 有序列表 |
| ` ```code``` ` | 代码块 |
| `**粗体**` `*斜体*` | 行内样式 |
| `---` | 分割线 |
| 短段落（3–5 行） | 阅读体验最好 |

### 会坏

| 写法 | 问题 | 替代 |
|---|---|---|
| Markdown 表格 | 打散成碎片 | 原生表格块 |
| `$` | 变公式 | 写"美元"/"USD"/"￥" |
| 超长段落 | 移动端糊成一坨 | 拆短 |
| 深层嵌套列表（>3 层） | 层级丢失 | 拍平 |
| 反复 append 拼代码块 | 内部多空行 | 一次性导入 |

## 图片与附件

- 插入本地图片：`lark-cli docs +media-insert --as user --doc <id> --file ./a.png --align center`
  （shortcut 已封装「上传 → 关联 → 校验 → 失败回滚」的多步编排）
- 只想拿上传凭证：`+media-upload`
- 下载文档里的素材：`+media-download`（自动识别扩展名）
- ⚠️ **受限文档的 `+media-download` 会 403**。此时别硬试，
  改走浏览器会话取图（见 `clone-and-migrate.md`）。

## 权限与可见性

新建文档默认可见性因租户而异。要"互联网获得链接即可访问"，需显式设置文档权限
（`drive` 域的权限成员/设置接口）。**别假设默认是公开**——用户拿到链接打不开是最常见的返工原因。

---

## 长文档 / 大内容的处理姿势

- **搜索与收集** 放子 agent，**主 session 负责写**。原因：子 agent 的输出上限会截断
  `content` 参数，写长文必炸。
- 必须先让子 agent 写时，任务描述里明确"**分块写入，每块 ≤3000 字**"。
- 长文本先落本地文件，再整体上传，别在命令行里塞超长字符串。
- 命令输出用 `head` / `tail` 限行，避免 context 被日志撑爆。

## 写完必须验证

```bash
lark-cli docs +fetch --as user --doc <doc_id_or_wiki_url> --format json > final.json
# 看 title / total_length / 图片标签数与空图片数
```

要核对的：

- [ ] 标题正确
- [ ] 总长度与预期量级一致（差太多说明内容被截断）
- [ ] **图片标签数 = 预期**，且**空 token 数 = 0**
- [ ] 代码块内容逐字一致
- [ ] 表格是真表格块，不是散文本（直接看渲染）
- [ ] 没有 `$` 引发的公式

## 错误对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| `400 Bad Request` | 单次内容过长 | 分块，≤1500 字 |
| 表格变碎片文本 | 用了 Markdown 表格 | 建原生表格块 |
| `$` 变公式 | LaTeX 解析 | 换"美元"/"USD" |
| `unsafe file path` | 传了绝对路径 | 改相对路径或走 stdin |
| 图片位置有空白 | 上传失败/空 token | 查 `+media-insert` 返回，重传 |
| 代码块多了空行 | 多次 append | 改成一次性导入 |
| 成功但读回来是空的 | **身份选错**（bot 读用户资源） | 显式加 `--as user` |
| 退出码 10 | 高风险写门禁 | 向用户确认后追加 hint 里的 flag 重试 |
